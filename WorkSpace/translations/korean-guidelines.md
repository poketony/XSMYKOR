# 미싱 이어 한국어 번역 지침

사용자가 XS2 채팅을 통해 전달한 최신 번역 방침을 일본어 원본 SWF 환경에 맞춰 정리한 기준이다. 지침 준비 자체는 새 장면 번역·리빌드·공개 배포 요청이 아니다. 기존 첫 독백 4문단은 글꼴과 진행을 확인한 테스트 초안이며 이번 준비 과정에서는 수정하지 않는다.

## 기준의 우선순위

사용자의 최신 확정 표기·지시와 해당 장면 원문을 먼저 적용한다. 의미와 표기가 충돌하는 것처럼 보이면 지시 대상을 확인하고 중요한 불확실성만 질문한다. 지정 DB는 명칭·설정 참고 자료이며, 다른 작품 말투 기록은 관계별 참고 근거다. 번역자 해석과 외부 윤문 처방을 인물의 대사 속 사실로 추가하지 않는다.

지정 DB는 `C:/Users/JO/XS3KOR/0.X30/mnu/kr/DBC.bin.KOR.txt`다. [DB 참고 방식](../../codex-lab/analysis/translation-notes/database-reference.md)과 [인물 말투](character-voices.md)를 함께 따른다. XS3 후반 진상을 미싱 이어 당시 인물이 이미 아는 정보로 쓰지 않는다.

## 사용자 확정 표기와 문장부호

최신 DB와 이후 사용자 변경을 확인한다. 여기에는 사용하지 않을 구표기를 병기하지 않는다. 표기 변경 시 정식 번역 입력과 파생 자료의 재생성 경로를 함께 확인하되 다른 저장소의 DB를 수정하거나 자동 연동하지 않는다.

- 원문의 `『』`·`「」` 구별과 중첩을 보존한다. 일반 큰따옴표는 `“…”`를 쓴다. JSON 문법이나 ActionScript의 문자열 구분자를 곡선 따옴표로 바꾸지 않는다.
- 원문에 마침표가 없으면 관성적으로 추가하지 않는다. 의도적으로 호흡을 끊는 경우는 예외다.
- `()`·`<>` 등의 반각은 별도 기능이 없고 정상 표시되는 경우 허용한다. 실제 HTML·제어 구문을 바꾸라는 뜻은 아니다. 화면에 표시되는 `<데이터베이스>` 같은 문구를 태그라고 단정하지 않는다.
- 한국어로 자연스러우면 원문의 정보 순서와 뒤에 놓인 호칭을 유지한다. 습관적으로 이름을 문장 앞으로 옮기지 않는다.
- `しゅにーん` 같은 늘임 호명은 `주임님~!`로 표현한다. 호칭 철자를 늘이거나 실제 말더듬과 혼동하지 않는다.
- 루비가 실제로 있으면 번역문에는 읽기를 일반 텍스트로 남기고 쓰기·루비 코드를 없앤다. 읽기만으로 부족할 때만 `읽기(쓰기)`로 보충한다. 원문 구획은 보존하며, 미싱 이어에 없는 루비나 XS2 제어코드를 새로 만들지 않는다.
- 본문에 표시되는 `[화자명]`은 번역 대상이지만 `[JPN]`·`[KOR]`·주소·ID는 구조 표식이다.
- `LOADING`·`NEXT`·`TO BE CONTINUED...`처럼 영문만으로 이루어진 문구는 번역하지 않는다. 숫자·공백·기호가 함께 있어도 원문 표기를 유지한다. `--- RECORDSEPARATOR ---`로 나뉜 독립 영문 구간(`cv`, 영문 크레딧·인명 등)도 원문으로 둔다. 해당 영문 텍스트의 원래 폰트·글리프·자간도 보존한다. 일본어와 영문이 한 문장에 섞인 경우는 전체를 영문 전용 항목으로 보지 않는다.

전달된 사용자 승인 어순·호칭 예문은 다음 두 줄이다. 끝 마침표를 추가하지 않는다.

```text
응, 물론이지
여기저기 구경시켜 줄게, 모모
```

이는 `うん もちろん / いろいろ案内してあげるわね モモちゃん`에 대응한다. 루비의 승인 예문은 읽기 `이 아이`가 KOS-MOS를 명백히 가리키는 장면의 `이 아이를 인계해야 하니까`다. 이 경우 괄호로 이름을 덧붙이지 않는다.

KOS-MOS의 특징적인 표현 기본형은 `도움이 된다면 기쁘겠습니다`다. 문맥·시제에 맞게 바꾸며, 도움을 준 뒤의 `お役に立てられ幸いです`는 `도움이 돼서 기쁩니다`가 승인 예문이다. 모든 상황이나 다른 인물에 고정 문구를 강제하지 않는다.

## 자연스러운 한국어로 편집하는 순서

1. 장면을 묶어 읽고 화자, 상대, 시점, 관계, 직전 사건과 발화 목적을 확인한다. 선택·분기·재사용을 구별하며 파일·심벌 순서를 실제 대화 순서로 단정하지 않는다.
2. 의미를 옮긴 뒤 일본어에서 잠시 떨어져 한국어 대화만 연속으로 읽는다. 인물의 호칭·존대·감정 흐름을 살펴 윤문한다.
3. 다시 일본어와 대조해 부정·조건·인과·수치·시제·추정의 강도·복선·정보가 드러나는 순서를 확인한다.
4. DB 표기, 관계별 말투, 데이터 형식과 실제 화면을 검수한다. 문장만 다듬은 결과와 실제 재생 검증을 구별한다.

`あなた/君/お前`를 모두 대명사로, `こと/もの/という/のだ`를 모두 명사절로 남기지 않는다. 불필요한 주어·접속사는 생략할 수 있지만 주체·책임·대조가 중요하면 유지한다. 짧게 만들려고 조사를 마구 생략하거나 모든 말을 보고체로 바꾸지 않는다.

원문에 없는 농담·욕설·유행어·감정·자기 낮춤·해설을 더하지 않는다. 인물의 거짓말과 오해를 번역자가 사실로 교정하지 않는다. 반복·침묵·중단·모호함의 기능을 보존한다. 같은 원문도 화자·상대·상황이 다르면 번역 재사용을 자동 확정하지 않는다.

한국어 편집에는 프로젝트의 `humanize-korean`을 보조로 쓸 수 있다. 대명사·접속사·반복·어미 변경 처방은 자동 치환 규칙이 아니다. 원문의 추정을 단정으로, 의도적 반복을 군더더기로 바꾸지 않는다. 외부 스킬의 일반 문체 지침보다 이 문서와 실제 원문이 우선한다.

## 미싱 이어 데이터와 화면 보존

정식 입력·빌더 범위는 [번역 데이터 안내](README.md)를 따른다. `[JPN]`과 `[KOR]`을 함께 보존한다. 기존 대사는 `[KOR]`이 없거나 빈 문자열·공백뿐이면 일본어를 유지한다. 음성 전용 장면의 새 자막은 같은 경우 생성하지 않는다. 분석용 대사 목록은 현재 빌더의 자동 입력이 아니다.

대사 호출, 동적 텍스트, 정적 글리프, 이미지·영상 속 문자, 재사용 심벌을 구분한다. 번역으로 ActionScript 식별자·경로·프레임 라벨을 바꾸지 않는다. 문자열의 따옴표·이스케이프·개행, 텍스트 필드의 HTML 여부는 실제 형식에 맞게 처리한다.

한글 폰트는 [사용자 지정 대응표](../README.md#폰트)를 따른다. A1·B1·B2는 a견고딕, A3·B3는 a고딕14이며, 미지정 A2와 공통 대사창·동적 설명은 기존 Galmuri11 Condensed를 유지한다. 영문 전용 항목과 독립 영문 구간은 원래 폰트를 유지한다. 필요한 한글과 `“…”`·`『』`·`「」`의 실제 글리프를 확인한다. 자동 줄바꿈·행간·행 수·박스 크기·화자 표시·NEXT·문자 타이핑과 완료 콜백을 해당 재생기에서 확인한다. XS2의 EUC 인코딩·SB/TXT·한글 치환표·폭 추정 수치를 가져오지 않는다. 표시 폭과 모바일 확대 적합성은 이 작품의 필드·폰트·실제 화면으로 판단한다.

자막 시간은 [자막 설계](../../codex-lab/analysis/subtitles.md)에 따라 소유 스프라이트의 로컬 프레임·진입·정지·재개·재진입을 기준으로 정한다. 번역 때문에 원본 프레임·음성 이벤트를 임의로 이동하지 않는다. 음성 전사는 별도 작업이며 화자·청취 근거·불명확 부분을 남긴다. 듣지 않은 음성을 DB나 문맥으로 상상해 채우지 않는다.

## 검증과 기록

시작 시점의 원본·작업본을 구별하고 사본 또는 해시를 남긴다. 첫/마지막 항목, BOM, CRLF/LF, 실제 레코드 수와 ID·원문·비대상 값 보존을 확인한다. 가나뿐 아니라 한자만 남은 본문도 살피되 코드·예제·의도적 일본어·표식을 구별한다.

도구 적용 성공, 번역 누락 검사, 글꼴·배치 확인, 음성·타이밍·진행 검증은 별개다. 문구 변경 후 과거 해시의 통과 기록을 현재 결과로 사용하지 않는다. 형식·크기 문제가 나면 먼저 의미를 지키며 간결하게 다듬고, 기술 작업이 필요하면 번역 변경과 구분한다.

장면별로 `장/소유 심벌/프레임 또는 대사 ID`, 화자·상대·시점, DB 조회 줄·주소, 의미 번역·한국어 편집·원문 재대조 상태, 형식 검사, 실제 재생 환경과 남은 문제를 짧게 기록한다. 사용자 승인, DB 사실, 다른 작품 용례, 번역자 초안·해석, 미확정을 구분한다. 자기 검수를 독립 감수라고 부르지 않는다.

분석·검증은 `codex-lab`에서 수행하고 검증한 결과만 반영한다. `original_asset`은 수정하지 않는다. 커밋·푸시는 사용자가 담당한다. 번역이나 지침 준비만으로 리빌드·배포·원본 교체를 시작하지 않는다.
